# Frontend endpoint parity

Last audited: 2026-09-20

Source of truth: `src/Web/Endpoints`. A route is **wired** only when an API-client
function (or shared transport service) is called by a real screen. **Missing** means
the backend route exists but the owning frontend has no complete workflow. Internal,
provider, and direct-link routes intentionally do not have ordinary screens.

## Current conclusion

The Storefront's implemented backend surface is wired except for optional ASP.NET
Identity account-management/session APIs. The Step 2 Agent screens are wired; the
current-Agent context endpoint remains unused because the shell currently derives its
identity from `/api/me`, and documented backend limitations still prevent network
server filtering and a payout-eligibility explanation. Admin parity remains
incomplete. The new Admin order discovery API removes the backend blocker, but its
frontend list, details, refund, and reconciliation workflow remains Step 3 work.
Real-stack E2E coverage must pass before Phase 12.10 can be marked complete.
