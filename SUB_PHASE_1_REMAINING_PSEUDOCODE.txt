1.2 — REMOVE AGENT-APPLICATION IMPERSONATION INPUT
==================================================

Implemented files:
    - Application/Network/Commands/ApplyAsAgent/ApplyAsAgentCommand.cs
    - Application/Network/Commands/ApplyAsAgent/ApplyAsAgentCommandHandler.cs
    - Application/Network/Commands/ApplyAsAgent/ApplyAsAgentCommandValidator.cs
    - Web/Endpoints/Agents.cs

PSEUDOCODE — ApplyAsAgent request and endpoint
-----------------------------------------------

DEFINE ApplyAsAgentRequest containing only:
    SponsorAgentId, optional

WHEN POST /organizations/{organizationId}/agents/applications is called:
    REQUIRE authenticated user
    CREATE ApplyAsAgentCommand using:
        OrganizationId from the route
        SponsorAgentId from the request body
    SEND command
    RETURN created Agent ID

DO NOT accept UserId from:
    request body
    query string
    route
    custom client header

PSEUDOCODE — ApplyAsAgentCommand
--------------------------------

DEFINE command containing:
    OrganizationId
    SponsorAgentId, optional

DO NOT include UserId.
DO NOT implement ICurrentUserScopedRequest because the command no longer contains
a client-selected user identity.

PSEUDOCODE — ApplyAsAgentCommandValidator
-----------------------------------------

REQUIRE OrganizationId is not empty

IF SponsorAgentId is supplied:
    REQUIRE SponsorAgentId is not empty

PSEUDOCODE — ApplyAsAgentCommandHandler
---------------------------------------

INJECT:
    IUser currentUser
    IApplicationDbContext database
    TimeProvider clock

HANDLE command:
    authenticatedUserId = currentUser.Id

    IF authenticatedUserId is missing:
        THROW unauthorized

    organization = FIND Organization
        WHERE Id equals command.OrganizationId

    IF organization does not exist:
        THROW not found

    IF organization is not active:
        THROW conflict or domain validation error

    existingAgent = FIND Agent
        WHERE OrganizationId equals command.OrganizationId
        AND UserId equals authenticatedUserId

    IF existingAgent exists:
        THROW conflict:
            "The current user already has an Agent profile in this Organization."

    IF command.SponsorAgentId is supplied:
        sponsor = FIND Agent
            WHERE Id equals command.SponsorAgentId
            AND OrganizationId equals command.OrganizationId

        IF sponsor does not exist:
            THROW not found

        IF sponsor is not active:
            THROW conflict or domain validation error

    generate unique AgentCode and ReferralCode

    agent = Agent.Apply(
        organizationId = command.OrganizationId,
        userId = authenticatedUserId,
        sponsorAgentId = command.SponsorAgentId,
        generated codes,
        joinedAt = clock.UtcNow
    )

    agent.SubmitForApproval()
    ADD agent
    SAVE
    RETURN agent.Id

PSEUDOCODE — optional Administrator-created application
-------------------------------------------------------

ONLY add this workflow if the product explicitly requires Administrators to create
applications for other users.

CREATE a separate command named CreateAgentApplicationAsAdministratorCommand.
DO NOT add UserId back to ApplyAsAgentCommand.

The Administrator command should:
    IMPLEMENT IOrganizationAdminRequest
    ACCEPT OrganizationId, target UserId, and optional SponsorAgentId
    VERIFY target identity exists
    VERIFY target identity belongs to or may join the Organization
    VERIFY Sponsor belongs to the same Organization and is active
    REJECT an existing Agent profile for the same Organization plus user
    CREATE the application
    AUDIT who created it and for whom


1.3 — OPTIONAL CHECKOUT IDENTITY-DERIVATION HARDENING
====================================================

The current verification design already satisfies the SDD. If manual CustomerId
input should be removed from the API contract, upgrade the existing checkout files.

PSEUDOCODE:
    REMOVE CustomerId from CreateCheckoutRequest
    REMOVE CustomerId from CreateCheckoutCommand
    INJECT IUser into CreateCheckoutCommandHandler
    REQUIRE currentUser.Id

    customer = FIND CustomerProfile
        WHERE OrganizationId equals command.OrganizationId
        AND UserId equals currentUser.Id

    IF customer does not exist:
        THROW not found or a dedicated profile-required error

    USE customer.Id for:
        referral attribution
        completed-purchase lookup
        Order creation

    KEEP every Product, Variant, referral Agent, commission profile, and Order query
    constrained by command.OrganizationId.

Do not perform this optional contract change without updating the Web request DTO,
frontend checkout client, and functional tests together.


1.4 — OPTIONAL FUTURE NETWORK-NODE VISIBILITY SCOPE
===================================================

Use only if a future endpoint allows an Agent to provide a separate target node ID.

PSEUDOCODE:
    DEFINE INetworkNodeScopedRequest implementing IAuthorizeRequest
    REQUIRE properties:
        OrganizationId
        RootAgentId
        TargetAgentId

    AUTHORIZE by calling:
        CanAgentInspectDownlineAsync(
            OrganizationId,
            RootAgentId,
            TargetAgentId
        )

    Authorization service returns true when:
        caller is an Administrator of OrganizationId
        OR caller owns RootAgentId
           AND a PlacementClosure row proves TargetAgentId descends from RootAgentId
           AND all involved rows belong to OrganizationId

PSEUDOCODE — Agent A versus Agent B protected reads
--------------------------------------------------

ARRANGE one Organization
ARRANGE authenticated Agent A
ARRANGE a different Agent B in the same Organization

FOR EACH protected request targeting Agent B:
    GetWalletSummary
    GetAgentEarningsSummary
    GetAgentCommissionHistory
    GetCommissionDetails
    GetBinaryVolumeSummary
    GetPairingHistory
    GetBinaryTree
    GetDownline
    GetDirectPlacementChildren
    GetPlacementAncestors
    GetDirectRecruits
    GetAgentLegSummary
    GetReferralDashboard
    GetReferralLink
    RegenerateReferralCode

    SEND request as Agent A
    ASSERT ForbiddenAccessException

ALSO SEND representative requests for Agent A's own ID
ASSERT authorization succeeds and handler executes

PSEUDOCODE — Administrator cross-Organization matrix
----------------------------------------------------

ARRANGE Organization A and Organization B
ARRANGE current Administrator belongs only to Organization A

FOR EACH Administrator mutation category targeting Organization B:
    Product or commission-profile mutation
    Commission-plan mutation
    Agent lifecycle or placement mutation
    Organization settings mutation
    Refund or reconciliation mutation

    SEND command
    ASSERT ForbiddenAccessException
    ASSERT no Organization B row changed

PSEUDOCODE — HTTP route and handler checks
------------------------------------------

Use WebApplicationFactory with PostgreSQL-backed test data.

CASE no authentication token:
    CALL a protected endpoint
    ASSERT HTTP 401

CASE authenticated user lacks required route role:
    CALL an Administrator endpoint
    ASSERT HTTP 403

CASE caller has the route role but belongs to another Organization:
    CALL endpoint with foreign OrganizationId
    ASSERT HTTP 403 from Application authorization

CASE caller is authorized but entity does not exist in owned Organization:
    CALL endpoint with unknown entity ID
    ASSERT HTTP 404

CASE request validation fails for an authorized caller:
    CALL endpoint with invalid fields
    ASSERT HTTP 400 or 422 according to the shared API policy

PSEUDOCODE — consistency assertions
------------------------------------

ASSERT:
    401 means no valid authenticated identity
    403 means identity is valid but scope is forbidden
    404 means caller may inspect the scope but the resource is absent
    cross-Organization requests do not reveal protected resource details
    failed authorization causes zero database writes
